# Next Share UI — 0.3.2

Reference: user's LocalSend screenshots. WPF uses MaterialDesignInXamlToolkit 5.3.2 and its MaterialDesign3.Defaults resources; this is a WPF implementation of Material 3, not Google's Android/Flutter toolkit.

Window: 830×560 logical pixels, matching the operator's current window; minimum 640×440. Normal window bounds are saved on close/exit. Sidebar: 200, with a 76-pixel icon rail below 740 width. Receive hero is measured inside a uniformly down-scaling Viewbox; it cannot overflow the space above the latest-file card. Rounded navigation pills, tonal cards, outlined actions and Material controls remain. Receive has two slowly rotating orbits and a softly breathing halo. The technical capability footer moved out of Receive; information remains in Details/Settings.

Tokens live in App.xaml and Services/AppTheme.cs: Surface, SurfaceContainer, SurfaceHigh, Primary, PrimaryContainer, OnPrimary, Ink, Muted, Outline, ErrorColor. Default teal primary #006B60; light surface #F4FAF7. Dark surface #101815, primary #83D5C2. Blue/violet accents are selectable. System theme follows the Windows app-color preference and updates on preference changes; high contrast uses Windows system colors. Animation respects Windows ClientAreaAnimation.

Receive: one shared power control; actual receiver name, live status, latest completed file and save-folder action. Default ON does not imply all transport capabilities are available. Detailed receiver state is available through the information button.

History: durable completed records; filename/device search, route filter, date/size/device metadata. File actions show its folder, copy path or hide its record. Clearing history persists hidden IDs and offers Undo; physical files and manifests remain. Empty results have a visible empty state. No sample records are injected into normal use.

Settings: save-folder picker, theme, accent, close-to-tray and separate desktop-notification/sound toggles with Preview. Controls persist preferences. Save-folder changes stop receivers first; previous file locations stay in history. Internal app-data roots cannot be selected as payload destination.

Receive feedback (0.4.4): accepted receive start shows a two-second arrival card; durable save updates History/Receive before a separate two-second completion card. Unknown lengths, concurrent devices and delayed completion are tracked independently. Quick Share succeeds only after its whole batch is committed; failed/partial batches do not show success. The 356x104 non-activating cards stack above the monitor work-area corner, also when hidden in the tray. These are transient app windows, not Notification Center entries. The original 0.78s glass chime is stereo PCM16 (identical front-left/right), with 250ms wake-up silence on both sides. Windows Media Engine retains the stream/player through MediaEnded; its own player volume never changes global endpoint volume. Settings selects Windows default or a specific active output and reports missing/muted outputs. Arrival bursts coalesce; completion sound waits for the active arrival sound. No Windows sound fallback. Regenerate with tools/generate-receive-chime.py; verify with tools/test-receive-chime.py.

Accessibility: keyboard-focus outline on navigation, automation names on icon controls, scalable logical units, Nirmala UI fallback for Bengali filenames, high contrast colors, opt-out of pulse animation and scrolling at the minimum window size.

Verification: isolated packaged app exercises actual view filtering/settings persistence and renders all three screens. Screen captures are generated by the WPF visual tree. Native phone receiving remains a separate interoperability test.

Send (0.4.0): sidebar destination between Receive and History. Four equal tonal File/Folder/Text/Paste tiles, selection count/size, removable rows, and an initial drag/drop hint. The whole window accepts file/folder/text drops without auto-sending. Selected files hide the redundant drop hint and use a bounded 80px selection list, keeping the first device card visible at 830x560. The entire Send page scrolls at 640x440. Nearby cards show the actual discovered name and route; paired Bluetooth entries may be cached and are identified as such. Refresh, scanning indicator, explicit empty/error guidance, accepted-byte progress, verification PIN and Cancel are connected to sender services. Device cards stay disabled without a selection or while preparing/sending. Themes use the existing app tokens. Only isolated smoke tests inject named fixture devices; normal startup never does.
